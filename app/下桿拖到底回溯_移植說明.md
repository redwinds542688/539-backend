# 「下桿拖到底＝回溯捲動」移植說明

> 來源：抓牌版 `抓牌.html`（2026-09-08，修正紀錄第 57、58、59、64、66 條）。
> 目的：讓另一支以「彩卷最新版_0907_0228」為底的主程式，照本文件加入同一個功能。
> 本文件裡的程式碼全部是從抓牌版直接抽出來的實際內容，可整段貼入；錨點字串則是主程式裡應該也存在的原始碼片段，貼入前請先用它們定位。

---

## 一、功能定義（使用者需求）

C 式（定位／合匯／差數）裡，下桿（B）的可動範圍是第 14～17 列。

1. **下桿已在 14，手指還繼續往上拖**：不要卡住，改成「捲動鍵」那套回溯：整個 16+4 視窗往前（舊）推——原第 16 期那列變成空白（被佔用列）、第 15 期變第 16 列、第 14 期變第 15 列……手指每多超出一列，回溯 k+1。
2. **下桿已在 17，手指還繼續往下拖**：反向，回溯 k−1，最小 0（＝現況，16 期有開＋4 期空白）。
3. **對稱**：手指在 14 上方往回下移，立刻 k−1；在 17 下方往回上移，立刻 k+1。手指回到第 14／17 列中心 ±半列以內，就回到「正常拖桿」狀態。
4. **平滑**：超出 14／17 之後表格跟著手指連續位移（translateY），不是一格一格跳；跨過半列才切換被佔用列；放手才對齊整列並重跑搜尋／統計。
5. **到上下限硬性停住**：k 已經是 0（或最大）時再拉，表格不動，沒有橡皮筋半格位移（第 66 條）。
6. **桿子不動、內容動**：滑動期間 A/B 錨定列改用固定在螢幕原位的半透明框顯示（整列所有號碼格，六合彩／大樂透含第 7 格特別號），號碼從框底下流過；A/B 圖釘與紅弧線留在原位；格子之間的連線先藏起來。放手對齊後移除固定框、重新上色。
7. **計算範圍不變**：統計／搜尋仍只用前 `cModeColCount()` 欄；上下桿塗到第 7 格純粹是顯示（第 64 條）。
8. **只在 C 式生效**；E 式等距（`window.eModeEqualDist`，下桿 16～19）不變。
9. **退出 C 式時回溯歸零**；表格重建（`buildPanels`）後若 k>0 要重新套用回溯視窗。

## 二、前提：主程式必須已經有這些東西

這個功能**完全沿用捲動鍵（2026-09-06「Ai框紅色圖釘：框住16期」）的回溯機制**，沒有另寫一套視窗邏輯。移植前請確認主程式已有：

| `let cModeScrollOffset=0;` | 回溯值 k |
| `getCModeScrollBaseWindow()` | 回傳 `{rows,startIndex,lastDataIndex,endIndex}` 的基準視窗 |
| `applyCModeScrollOffset(k)` | 依 k 設定每個 `tr` 的 display 與 `c-scroll-blanked` |
| `resetCModeScrollOffset()` | k 歸 0 並清掉 `c-scroll-blanked` |
| `(function bindCModeScrollGesture(){ ... })();` | 捲動鍵手勢的 IIFE，裡面有 `findTable()`、`measure()`、`setT(px,animate)`、`applyBlankClasses(k)`、`prepare()`，以及閉包變數 `tableEl, scEl, scOverflowBackup, rowLocal, rowVis, maxK, baseT, kNow, win` |
| CSS `table.road tr.c-scroll-blanked ...`、`tr.c-scroll-peek` | 被佔用列與備列樣式 |
| `normalizedNum(td)` 把 `c-scroll-blanked` 列當空白 | 統計／搜尋才會把被佔用列視為未開 |

**如果主程式沒有捲動鍵那套（沒有 `bindCModeScrollGesture`），請先把整個 IIFE 與 `applyCModeScrollOffset` 一族移植過去，本文件才適用。**
（抓牌版後來把捲動鍵的「雙擊開啟」拿掉了——第 60 條——但 IIFE 本身必須保留，因為下面的平滑 API 就住在裡面。主程式要不要拿掉捲動鍵，跟本功能無關。）
