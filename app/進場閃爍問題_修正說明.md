# 「16+4 先滿屏再縮回」（進場閃一下）問題的診斷與修正說明

> 來源：抓牌版 `抓牌.html`（2026-09-08，修正紀錄第 65 條）。
> 目的：讓另一支以「彩卷最新版_0907_0228」為底的主程式，照本文件檢查並修正同一個問題。
> 主程式的這幾段程式碼與抓牌版是同一套來源，**極可能有一模一樣的錯**，請務必逐項核對。

---

## 一、現象

C 式（定位／合匯／差數）裡，16+4 開獎單本來應該一直是「向右壓縮、左側留給 Ai 欄」的樣子。
但使用者經常看到：先出現一瞬間**滿屏、未壓縮**的表格，接著才縮回壓縮後的樣子（閃一下）。

用無頭 Chromium 每一幀偵測「`.scroller` 看得見（visibility 不是 hidden）但 inline style 沒有 `scaleX` 壓縮」，結果：

| 觸發路徑 | 可見且未壓縮的幀數 |
|---|---|
| 進 C 式差數 | 0 |
| C 式裡 `loadData()`（切回 App 重載） | **6～7 幀（約 100～220ms）** |
| C 式裡 `runHomeInitialReset()+loadData()`（pageshow／visibilitychange） | **7 幀** |
| C 式裡 `manualUpsertDrawRecord()`（GitHub 同步／手動輸入新增一筆） | **7 幀** |
| 下桿拖到底回溯 | 0 |
| 視窗高度改變（網址列收合） | 0 |

結論：**只要 C 式裡表格重建（`buildPanels`），就會閃**。而事件時序紀錄裡，本來應該擋住這段的遮罩 `c-ding-entering`，**從頭到尾沒有掛上**（沒有任何「mask ON」）。

---

## 二、根本原因（兩個錯，同一個來源）

### 錯誤 1：遮罩判斷用了閉包裡的變數，全域函式讀不到

`cModeActive`、`recentOnly`、`applyCCompactLayout`、`compactDayCellsForPeriod16` 都宣告在 `setupImageView()` **閉包內**（`let cModeActive=false;` 在那個函式裡面）。
而 `buildPanels()` 是**全域**函式，讀不到它們。

2026-09-05 為了修這個閃爍，在 `buildPanels` 開頭加了：

```js
if(typeof cModeActive!=="undefined"&&cModeActive&&!document.body.classList.contains("c-ding-entering")){document.body.classList.add("c-ding-entering");setTimeout(function(){document.body.classList.remove("c-ding-entering")},4000)}
```

在全域裡 `typeof cModeActive` 永遠是 `"undefined"`，整個判斷永遠 false，**遮罩從加上去那天起一次都沒生效**。
`typeof x!=="undefined"` 這種寫法把「讀不到變數」這個錯誤安靜地變成「永遠不執行」，所以一直沒被發現。

同一段裡還有兩處同病：
- 定期十六（非 C 式）的遮罩分支：`typeof cModeActive!=="undefined"&&!cModeActive&&...&&typeof recentOnly!=="undefined"&&recentOnly` → 永遠 false。
- 「重建後 rAF×2 重新壓縮」：`typeof cModeActive!=="undefined"&&cModeActive&&typeof applyCCompactLayout==="function"` → 永遠 false（從未執行過；重建後的重新壓縮實際上一直是 `__reapplyMagnifierState()` 尾端在做）。

程式裡其實早就有人踩過同一個坑：抓牌版第 8 條的註解寫著「原本用 cModeActive 變數判斷，但那是 setupImageView 閉包內的變數、這裡讀不到」，並改用 body class。只是這幾處漏改。

### 錯誤 2：`boot()` 的 visibilitychange 直接寫 `if(cModeActive)`，沒有任何保護

```js
if(cModeActive){document.body.classList.add("c-ding-entering");setTimeout(function(){document.body.classList.remove("c-ding-entering")},4000)}loadData();syncCrawlerDataFromGithub().catch(...)
```

`boot()` 也是全域函式。切回 App 超過 1 分鐘（過了 `VISIBILITY_REFRESH_COOLDOWN_MS` 的節流）走到這行時會丟 **ReferenceError: cModeActive is not defined**，整個監聽器中止，**後面的 `loadData()` 與 GitHub 同步都不會執行**。這是順帶抓到的第二個 bug：切回 App 不更新資料。

## 三、修正方法：一律改用 body class 判斷

C 式啟用時 body 一定有 `c-mode-active`（加／移除各只有一處，與 `cModeActive=true/false` 成對）；定期十六／E 式畫面 body 有 `magnifier-mode` 與 `recent-only-mode`。這些 class 在任何作用域都讀得到。

### 修改 1：`buildPanels()` 開頭，C 式遮罩判斷

**錨點（原始碼）**：

```js
if(typeof cModeActive!=="undefined"&&cModeActive&&!document.body.classList.contains("c-ding-entering")){document.body.classList.add("c-ding-entering");
```

**改成**：

```js
/* 第65條(2026-09-08)：使用者回報「16+4常常先滿屏再縮回」。抓到原因——cModeActive/recentOnly是setupImageView()閉包內的變數，buildPanels()是全域函式讀不到，typeof永遠是"undefined"，這個遮罩從2026-09-05加上去到現在一次都沒掛上(時序紀錄裡完全沒有mask ON)。改用body class判斷(第8條已用同一招) */if(document.body.classList.contains("c-mode-active")&&!document.body.classList.contains("c-ding-entering")){document.body.classList.add("c-ding-entering");setTimeout(function(){document.body.classList.remove("c-ding-entering")},4000)}
```

### 修改 2：`buildPanels()` 開頭，定期十六遮罩判斷（緊接在修改 1 之後的 `else if`）

**錨點（原始碼）**：

```js
else if(typeof cModeActive!=="undefined"&&!cModeActive&&document.body.classList.contains("magnifier-mode")&&typeof recentOnly!=="undefined"&&recentOnly&&!document.body.classList.contains("c-ding-entering")){
```

**改成**：

```js
else if(!document.body.classList.contains("c-mode-active")&&document.body.classList.contains("magnifier-mode")&&document.body.classList.contains("recent-only-mode")&&!document.body.classList.contains("c-ding-entering")){/* 第65條：同上，recentOnly改用body.recent-only-mode */document.body.classList.add("c-ding-entering");setTimeout(function(){document.body.classList.remove("c-ding-entering")},4000)}
```

### 修改 3：`buildPanels()` 裡「重建後 rAF×2 重新壓縮」那段——**不要啟用**，只加註解

**錨點（原始碼）**：

```js
if(typeof cModeActive!=="undefined"&&cModeActive&&typeof applyCCompactLayout==="function"){requestAnimationFrame(function(){requestAnimationFrame(function(){if(typeof compactDayCellsForPeriod16==="function")compactDayCellsForPeriod16();applyCCompactLayout()})})}
```

這段從未執行過，重建後的重新壓縮一直由 `__reapplyMagnifierState()` 尾端的 rAF×2 負責。**保留原樣（死碼）即可，不要改成 body class 讓它活過來**，否則會有兩條路徑各壓一次。抓牌版只在前面加了一行註解說明。

### 修改 4：`boot()` 的 visibilitychange 監聽

**錨點（原始碼）**：

```js
if(cModeActive){document.body.classList.add("c-ding-entering");setTimeout(function(){document.body.classList.remove("c-ding-entering")},4000)}loadData();
```

**改成**：

```js
/* 第65條：原本寫if(cModeActive)——這裡是全域的boot()，cModeActive是閉包變數，切回App超過1分鐘走到這行會丟ReferenceError，後面的loadData()/GitHub同步整個不執行。改用body class */if(document.body.classList.contains("c-mode-active")){document.body.classList.add("c-ding-entering");setTimeout(function(){document.body.classList.remove("c-ding-entering")},4000)}loadData();
```

### 確認遮罩 CSS 存在（不用改，只確認）

`c-ding-entering` 的 CSS 必須有把 `.scroller` 藏起來，否則遮罩掛了也沒用。抓牌版的規則長這樣（節錄）：

```css
body.c-ding-entering .scroller, body.c-ding-entering #connect-svg, body.c-ding-entering #data-blank-divider-line, body.c-ding-entering #c-mode-b-handle, body.c-ding-entering #c-mode-a-handle, body.c-ding-entering #c-mode-arc-svg, body.c-ding-entering #c-mode-ding-arcs-svg, body.c-ding-entering #c-mode-ding-lines-svg, body.c-ding-entering #c-mode-drag-lines-svg, body.c-ding-entering #c-mode-ding-auto-drag-lines-svg, body.c-ding-entering #e-mode-nine-line-lines-svg, body.c-ding-entering #e-mode-a-coin, body.c-ding-entering #blank-period-right-line-overlay, body.c-ding-entering #c-ding-left-blank-frame, body.c-ding-entering #c-ding-ai-box{ visibility:hidden !important; }
```

（同一批規則還藏 `#c-ding-ai-box`、`#c-ding-left-blank-frame`、各條連線 SVG。）

## 四、修完應該看到的時序

抓牌版修後，C 式裡 `loadData()` 的事件時序：

```
   16ms  logEvent 重畫表格 — buildPanels
   25ms  mask ON                         ← buildPanels 開頭掛上遮罩（修前完全沒有這行）
   25ms  scroller transform: "scaleX(0.83346)" → ""   ← 重建前清掉壓縮，但已被遮罩擋住
  128ms  panels transform: "none" → "scale(4.06, 3.93)"
  223ms  logEvent C式定位 — 16+4向右縮到紅線 scaleX=0.8335
  226ms  scroller transform: "" → "scaleX(0.83346)"
  247ms  mask OFF                        ← 壓縮繪製完成後 rAF×2 才揭幕
```

所有觸發路徑「可見且未壓縮」幀數都變成 0。

## 五、驗證步驟

1. **語法**：改完把每個 `<script>` 內容用 `new Function()` 檢查一次不報錯。
2. **閃爍偵測**（建議用無頭 Chromium 或在真機加暫時程式）：進 C 式後，用 `requestAnimationFrame` 迴圈每幀檢查
   `getComputedStyle(document.querySelector(".scroller")).visibility!=="hidden"` 且 `!/scaleX/.test(scroller.style.transform)` 且 body 有 `c-mode-active`，
   符合就記一筆。依序觸發 `loadData()`、`window.runHomeInitialReset(); loadData()`、`manualUpsertDrawRecord("539","2026-09-06",[1,2,3,4,5],null)`，每條路徑記到的幀數都必須是 **0**。
3. **切回 App 路徑**：進 C 式後等 61 秒以上，切到別的 App 再切回來（或以 `Object.defineProperty(document,"visibilityState",{get:()=>"visible"})` 後 `dispatchEvent(new Event("visibilitychange"))` 模擬）。瓢蟲紀錄要有「切回App：觸發loadData()」且**沒有** ReferenceError；修前這裡會有 `cModeActive is not defined`。
4. **不可退步**：首頁、全頁、C 式進場畫面與改前逐像素相同；C 式靜止時 DOM 無變動。

## 六、給主程式的額外檢查（同類錯誤可能不只這幾處）

在主程式裡搜尋下面這些字串，凡是出現在 **全域函式**（`buildPanels`、`loadData`、`boot`、`manualUpsertDrawRecord`、`syncCrawlerDataFromGithub`、`loadLotteryLocalDBIntoEmbedded` 等，也就是不在 `setupImageView(){...}` 大括號範圍內的）裡的，都要改成 body class 或 `window.*` 掛出來的函式：

- `typeof cModeActive`、`cModeActive`
- `typeof recentOnly`、`recentOnly`
- `typeof applyCCompactLayout`、`typeof compactDayCellsForPeriod16`
- `cModeAPeriod`、`cModeBPeriod`、`cModeScrollOffset`（同樣是閉包變數）

判斷方式：在瀏覽器主控台直接輸入 `typeof cModeActive`，回 `"undefined"` 就代表它不是全域，任何全域函式裡對它的判斷都是假的。

**鐵律**：模式判斷請用 body class（`c-mode-active`、`magnifier-mode`、`recent-only-mode`、`pinch-fullscreen-mode`）；需要在全域呼叫閉包內函式時，用閉包裡 `window.xxx=xxx` 明確掛出來（例如 `window.__reapplyMagnifierState`、`window.runHomeInitialReset` 就是這樣做的）。
