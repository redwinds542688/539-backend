# 定期十六 截圖初始檔

記錄「定期十六」模式**存檔擷取**（`saveAsImage()` 內，`wasRecentOnlyMode === true` 分支）目前的所有邏輯與參數，做為之後調整的基準版本。跟「定期16 初始檔.md」是兩份獨立文件——那份記錄的是**畫面顯示**邏輯（`applyRecentOnly()`），這份記錄的是**存檔擷取**當下的邏輯，兩者不要混在一起改。

---

## 一、整體策略：與一般存檔、A3/A4 完全脫鉤

- 「定期十六」的截圖是完全獨立的功能，跟「印單」鍵的 A3/A4 紙張設定**無關**，也跟一般「存檔」鍵（`saveAsImage()` 裡 `wasRecentOnlyMode === false` 那個分支）分開處理。
- `triggerPngDownload(canvas, filename, skipPaperFit)`：呼叫時第三個參數傳 `wasRecentOnlyMode`，`true` 時完全跳過「加寬5%」跟「等比例縮放置中塞進A3/A4、補白邊」這兩段邏輯，直接輸出畫布本身的原始尺寸（滿版全螢幕，不留白）。
- `PERIOD_SHOT_TUNE.padRatio = 0`：「定期」的存檔不加任何四周留白（`SAVE_IMG_TUNE`／一般存檔維持 `0.01`，兩者分開設定，改一邊不會影響另一邊）。

---

## 二、紅色外框（16方塊區邊界）

- 平常瀏覽時，`body.recent-only-mode .scroller{ border-color:#e02020; }`（紅框），用來幫使用者一眼看出「16方塊區」邊界。
- **只有存檔擷取當下**要把紅框拿掉、改回黑色：
  ```css
  body.recent-only-mode.capturing-plain .scroller{ border-color:#000; }
  ```
  這條規則的選擇器比上面那條多一個 class（`.capturing-plain`），特異度更高，只在 html2canvas 正在擷取畫面的當下（body 同時有 `recent-only-mode` 跟 `capturing-plain` 兩個 class）才生效。擷取結束、`capturing-plain` 被移除之後，畫面上自動變回紅框，不影響使用者接下來瀏覽。

---

## 三、開獎號碼字體與位置

### 3.1 字體縮小 20%
```css
body.capturing-plain table.road td.num{ font-size:8.168px; }
```
原本 `10.21px`，縮小 20% 後的數值。只影響存出來的圖片，不影響畫面上瀏覽時的字體大小。

### 3.2 全部號碼往上移動（CSS，一般數字用 html2canvas 原生畫）
```css
body.recent-only-mode.capturing-plain table.road td.num .cell-shift{ transform:translate(-20%, -35%); }
```
原本 `-30%`，累計往上多移動 5% 變成 `-35%`。

### 3.3 圈起來的數字（第一招，JS 手動補畫）位置修正
- 定位基準點：跟圓形用**同一個**基準點（格子中心 `cx`、`cy`），不要另外讀 `.cell-shift` 自己的 `getBoundingClientRect()`（那個位置因為 `transform:translate(0%,10%)` 這類視覺微調，跟圓形的「整個格子置中」基準不一致，會對不齊）。
- Canvas 2D 的 `textBaseline:"middle"` 是用整個字體（含英文字母上下伸出部分）的中線去算「置中」，跟數字本身（沒有下伸筆畫）的視覺中心有落差，數字類字符用這個屬性置中普遍會偏高。加一個向下修正值，目前是字體大小的 **3%**（原本 8%，往上移動 5% 之後降到 3%，跟 3.2 的 CSS 位移幅度保持一致）：
  ```js
  const baselineCorrection = fontPx * 0.03;
  ctx.fillText(text, cx, cy + baselineCorrection);
  ```

## 四、第一招（圓形標記）

### 4.1 為什麼要手動補畫
第一招的圓形是用「絕對定位偽元素 + `transform:translate(-50%,-50%)` 置中」畫的（CSS `::before`），這個偽元素本身的 transform，疊在「定期」極端、非等比例的 `transform:scale()` 裡面，html2canvas 的渲染引擎在這種「transform 疊 transform」又是非等比例縮放的情況下精準度不夠，會畫出破圖（數字/圓形錯位重疊）。

修法：只在 `capturing-plain` 情境下，把原生圓形偽元素隱藏掉：
```css
body.capturing-plain table.road td.num.num-marked.num-marked-click::before{
  background:transparent !important;
  border:none !important;
}
```
改由 JS 在 `saveAsImage()` 裡的 `drawCircleMarksOntoCanvas()`（只在 `wasRecentOnlyMode` 時執行）手動用 Canvas 2D 補畫。

### 4.2 圓形大小：強制撐滿格子高度
不再用「font-size × 縮放比例」去猜圓形大小（那樣算出來的比例常常跟畫面實際大小對不上，因為 `getComputedStyle` 讀到的 font-size 不會反映 `transform:scale()` 造成的視覺放大）。改成直接強制圓形一定要碰到上格線下緣、下格線上緣：
```js
const diameter = r.height * captureScale;
```
（`r` = 該格子的 `getBoundingClientRect()`）

### 4.3 圓形畫完後，補畫格線
因為圓形撐滿了整格高度，會蓋住格子本身跟上/下相鄰格共用的那條格線。圓形跟外框都畫完之後，**額外把這一格的上邊界、下邊界重新畫一條細線蓋在最上層**：
```js
const cellScaleForBorder = r.width / 28.12;
const gridLineW = Math.max(1, 1 * cellScaleForBorder * captureScale);
// 上格線再往上移動5%（以格子高度為基準）
const yTop = (r.top - outerRect.top) * captureScale + pad - r.height * captureScale * 0.05;
const yBottom = (r.top + r.height - outerRect.top) * captureScale + pad;
ctx.strokeStyle = "#bbb"; // 比照一般格線顏色
ctx.lineWidth = gridLineW;
// 分別畫 yTop、yBottom 兩條橫線，範圍是該格子的左右邊界
```
星期分隔線（月份起始列，見第五節）另外有 `drawWeekStartLinesOntoCanvas()` 專門補畫特殊的粗黑線，執行順序在這之後，會覆蓋掉這裡畫的一般細線，兩者不衝突。

### 4.4 圓形文字對齊
見第三節 3.3。

## 五、星期分隔線（`.month-start`，539/天天樂實際上是星期一分隔線）

### 5.1 為什麼要手動補畫
這條線原本是用 `box-shadow: inset 0 0.6px 0 0 #000` 畫的。跟第一招圓形同一類問題：html2canvas 對 box-shadow 在「定期」極端非等比例縮放下算不準，畫出來會變成看起來像陰影的黑色色塊。

修法：只在 `capturing-plain` 情境下，把原生 box-shadow 隱藏掉：
```css
body.capturing-plain table.road tr.month-start td{ box-shadow:none !important; }
```
改由 JS 手動補畫（`drawWeekStartLinesOntoCanvas()`，只在 `wasRecentOnlyMode` 時執行）。

### 5.2 補畫邏輯
量每一列（`tr.month-start`）第一格、最後一格目前實際渲染的位置，橫線從最左畫到最右，粗細比照 CSS 原本的 `0.6px`（乘上該列的縮放比例、再乘上截圖倍率 `captureScale`）：
```js
const NATURAL_CELL_WIDTH = 28.12;
const cellScale = firstRect.width / NATURAL_CELL_WIDTH;
const lineW = Math.max(1, 0.6 * cellScale * captureScale);
```

## 六、連接線（第三招）

### 6.1 一般座標換算
獨立蓋在整個畫面上的一層（`position:fixed`），html2canvas 只截到開獎單本身那一層，線不會自動被截進去，改成用 Canvas 2D 手動補畫（`drawConnectionsOntoCanvas()`，一般存檔跟「定期」都會執行，不是「定期」專屬）。

### 6.2 粗細縮減 40%（「定期」專屬）
```js
const lineWidthMultiplier = wasRecentOnlyMode ? 0.6 : 1;
ctx.lineWidth = tune.lineWidthScale * captureScale * lineWidthMultiplier;
```
只影響「定期」的截圖，不影響一般存檔／畫面上實際看到的連接線粗細。**是粗細，不是長度**——線的起點/終點座標計算完全沒變。

## 七、待確認 / 尚未定案

- 第四節 4.3 的「上格線再往上移動5%」是目前最後測試的版本，若使用者之後回報「格線位置怪怪的」，優先檢查這個 `-5%` 修正是否還適用。
- 目前所有數值（8.168px、-35%、3%、0.6 倍粗細、5% 上移）都是根據多輪使用者截圖比對得出的經驗值，不是理論算出來的精確值。如果之後畫面本身的縮放邏輯（`applyRecentOnly()`）有調整，這些數值很可能需要重新校正。
